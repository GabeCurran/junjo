# Java SDK

The Junjo.io SDK for Java (`io.junjo:junjo-sdk`) is a Java 21 client library for game servers and backends on the JVM. It covers groups, members, roles, permission checks, game bans, sanctions, linked identities and the [game stream](/api-reference/events#get-v1events) behind a `JunjoClient` whose every call returns a `CompletableFuture`. On top of the HTTP surface it ships three pieces built for servers that must keep running when the backend is slow or away:

- **`PermissionResolver`**: the server's resolution algorithm in Java, held to the same conformance vectors, for local checks with no network call.
- **`GameMirror`**: an in-memory copy of role graphs, the game ban list, sanctions and tracked members, kept current from the game stream and readable from any thread without locks or I/O. It can persist itself to a file and answer from it at startup.
- **`WriteQueue`**: a durable, ordered queue of writes on disk that survives a crash and replays safely with idempotency keys and version checks.

This is a server-side SDK. The per-game API key (`jk_<prefix>.<secret>`) is a full-control credential; keep it inside your game server or backend, never in a client binary players can read.

## Requirements

| Requirement | Notes |
|-------------|-------|
| Java 21+ | The library is compiled with `--release 21` and ships a `module-info` (module `io.junjo.sdk`). |
| Gson 2.11.0 | The only runtime dependency besides the JDK. HTTP is the JDK's `java.net.http`. |

## Quick start

```java
import io.junjo.sdk.*;
import io.junjo.sdk.model.*;

JunjoClient junjo = JunjoClient.builder()
        .baseUrl("https://api.junjo.io")
        .apiKey(System.getenv("JUNJO_API_KEY"))
        .build();

String player = Ids.namespaced("mc", playerUuid);   // "mc:2f0c1a3b-..."

junjo.members().add("grp_main", player, "role_member", null, WriteOptions.idempotent())
        .thenAccept(member -> System.out.println("version " + member.version()))
        .exceptionally(err -> {
            JunjoException e = (JunjoException) err.getCause();
            System.err.println(e.code() + ": " + e.getMessage());
            return null;
        });
```

Namespaces on the client:

| Namespace | Calls |
|-----------|-------|
| `groups()` | `get`, `create`, `list`, `update`, `delete`, `restore`, `inviteByUserId`, `inviteByCode`, `acceptInvitation`, `declineInvitation`, `join`, `leave`, `kick`, `ban`, `unban`, `banHistory`, `setRelationship`, `clearRelationship`, `getRelationship`, `listRelationships`, `setParent`, `listChildren`, `batch` |
| `invitations()` | `list`, `get`, `revoke` |
| `members()` | `add`, `get`, `list`, `getAccess`, `getAccessMany`, `setMetadata`, `setNotes`, `assignRole`, `removeRole`, `overridePermission`, `clearPermissionOverride`, `importMembers` |
| `roles()` | `create`, `get`, `list`, `update`, `delete`, `setEntries`, `grantPermission`, `revokePermission`, `setParents`, `getGraph` |
| `permissions()` | `check`, `checkBatch` (split into chunks of 100) |
| `bans()` | `add`, `remove`, `get`, `list`, `moderation` (with sanctions) |
| `sanctions()` | `add`, `remove`, `list`, `forUser`, `history` |
| `identities()` | `list`, `requestLinkCode`, `redeemLinkCode`, `unlink`, `setDisplayName`, `findByName` |
| `events()` | `position`, `subscribe` |
| `export()` | `read`, `open` |

Return types follow two rules:

- **Every paged list returns `JunjoResponse<Page<T>>`**: `groups().list`, `groups().banHistory`, `members().list`, `invitations().list`, `bans().list`, `sanctions().list` and `sanctions().history`. Reads that carry a [stream position](/api-reference/events#snapshots-and-the-stream) or an `ETag` return a `JunjoResponse` too (`roles().getGraph`, `roles().list`, `members().getAccess`, `members().getAccessMany`, `bans().moderation`, `sanctions().forUser`, `identities().list`). `JunjoResponse` has `value()`, `streamPosition()` and `etag()`; the last two are null when the server sent none.
- **Single-resource reads return an `Optional`**, empty for `not_found`: `groups().get`, `groups().getRelationship`, `members().get`, `roles().get`, `bans().get`, `invitations().get`.

`close()` the client on shutdown: pending calls fail with `cancelled`, and the SDK's daemon threads and connections are released.

### From the TypeScript SDK

The Java names match the TypeScript SDK's. The differences come from Java itself:

| TypeScript | Java |
|------------|------|
| `members.add(groupId, userId, { roleId, actorUserId })` | `members().add(groupId, userId, roleId, actorUserId, opts)` |
| `members.import(groupId, input)` | `members().importMembers(groupId, request)` (`import` is a Java keyword) |
| `members.getAccess(groupId, userId)` (null for a non-member) | `members().getAccess(groupId, userId)` (fails with `not_found` for a non-member) |
| `members.getAccessMany(groupId, userIds)` | `members().getAccessMany(groupId, userIds)`, a list of `Optional` |
| `members.overridePermission(...)`, `members.clearPermissionOverride(...)` | same names |
| `roles.grantPermission(roleId, key, { value })` | `roles().grantPermission(roleId, key)` or `grantPermission(roleId, key, value, opts)` |
| `roles.getGraph`, `roles.setEntries`, `roles.revokePermission` | same names |
| `groups.kick`, `groups.ban`, `groups.unban`, `groups.join`, `groups.leave`, `groups.restore`, relationships, `setParent`, `listChildren` | same names |
| `groups.update(id, { name, actorUserId }, { ifMatch })` | `groups().update(id, UpdateGroupInput.builder().name(...).actorUserId(...).build(), WriteOptions.none().withIfMatch(group.version()))` |
| `groups.delete(id, { hard, actorUserId, ifMatch })` | `groups().delete(id, hard, actorUserId, opts)` |
| `groups.kick(groupId, userId, { reason, actorUserId })` | `groups().kick(groupId, userId, reason, actorUserId, opts)` |
| `groups.setRelationship(a, b, type, { mutual, actorUserId })` | `groups().setRelationship(a, b, type, mutual, actorUserId, opts)` |
| `new Junjo({ writeTag })`, `{ writeTag }` on a write | `JunjoClient.builder().writeTag(tag)`, `WriteOptions.withWriteTag(tag)` |
| `groups.batch(groupId, ops, { ifMatch })` | `groups().batch(groupId, List.of(GroupBatchOp.memberRoleAdd(...), ...), WriteOptions.none().withIfMatch(group.version()))` |
| `junjo.export({ records, groupKinds })` | `export().read(ExportOptions.all().withRecords(...).withGroupKinds(...), consumer)` |
| `bans.add(input)` | `bans().add(CreateBanInput)` |
| `sanctions.add(userId, AddSanctionInput)` | `sanctions().add(AddSanctionInput)`; the user id is part of the input's builder |
| `isNotActive(err)` | `JunjoException.isNotActive()` |
| `events.subscribe(handler, { types: ["game.user.banned"] })` | `events().subscribe(listener, SubscribeOptions.builder().types(EventType.GAME_USER_BANNED).build())` |
| options objects (`{ idempotencyKey, ifMatch }`) | `WriteOptions.idempotent().withIfMatch(version)` |
| `members.add(groupId, userId, { ifNoneMatch: "*" })` | `members().add(groupId, userId, roleId, actorUserId, WriteOptions.idempotent().withIfNoneMatchAny())` |
| `Promise<T>` | `CompletableFuture<T>` |

Argument order follows the TypeScript SDK in the API classes: member calls take `(groupId, userId)`, permission checks take `(userId, groupId, permission)`. `GameMirror` has no TypeScript counterpart and takes the user first everywhere, as `permissions().check` does: `check(userId, groupId, permission)`, `track(userId, groupId)`, `access(userId, groupId)`.

## Errors

Every failure is a `JunjoException`, wrapped in a `CompletionException` when you `join()`:

| Accessor | Meaning |
|----------|---------|
| `code()` | The server's [error code](/api-reference/errors), or an SDK code: `network_error`, `timeout`, `cancelled`, `invalid_wire_data`, `stream_overflow`, `unknown` (a non-2xx answer without the envelope). |
| `status()` | The HTTP status; `0` when no response arrived. |
| `requestId()` | The server's correlation id. |
| `retryAfterSeconds()` | The `Retry-After` header. |
| `details()` | The envelope's optional `details` object. `importRowErrors()` reads a bulk import's failing rows from it. |
| `opIndex()` | The index of the op that failed a [group batch](#group-batches), from `details.opIndex`; empty for any other failure. |
| `isNotActive()` | True for a lift with nothing to lift: `404 not_found` with `details.reason: "not_active"`. |

Unknown server codes pass through unchanged; keep a default branch when switching on `code()`.

## Timeouts and retries

Every call has a connect timeout (default 10 s) and a request timeout that covers the whole response, body included (default 30 s). Both are set on the builder.

Calls that are safe to repeat retry automatically: GETs, the read-only POSTs (`checkBatch`, `getAccessMany`), and writes that carry an `Idempotency-Key`. They retry on network errors, timeouts, 5xx, 408, 429 and 409 `idempotency_key_in_progress`, up to `maxAttempts` (default 3), with exponential backoff and full jitter. A `Retry-After` header is honoured exactly, up to `RetryPolicy.maxRetryAfter` (30 s); a longer one fails the call at once. Other writes are sent once.

## Groups

`groups()` covers the whole group lifecycle: create, read, update, delete and restore; membership by invitation, open join and leave; kicks and per-group bans with their history; relationships between groups; and the sub-group hierarchy. `invitations()` lists a group's invitations, looks one up by code and revokes one; creating, accepting and declining live on `groups()`.

```java
Group group = junjo.groups().get("grp_main").join().orElseThrow();

// Rename, attributed to a moderator, only if nobody changed the group since the read.
Group renamed = junjo.groups().update("grp_main",
        UpdateGroupInput.builder().name("Main").actorUserId(moderatorId).build(),
        WriteOptions.idempotent().withIfMatch(group.version())).join();

// Invitations: one addressed to a user, and an open code that expires in a week.
Invitation direct = junjo.groups().inviteByUserId("grp_main", player, "role_member", WriteOptions.idempotent()).join();
Invitation open = junjo.groups().inviteByCode("grp_main", null, "7d", WriteOptions.idempotent()).join();
junjo.groups().acceptInvitation(open.code(), otherPlayer).join();
junjo.invitations().revoke(direct.code());

// Kick and relationship writes carry an optional actor.
junjo.groups().kick("grp_main", player, "spam", moderatorId, WriteOptions.idempotent());
junjo.groups().setRelationship("grp_main", "grp_rival", "enemy", true, moderatorId, WriteOptions.idempotent());

// Soft delete (undo with restore) or hard delete, with an actor and a version check.
junjo.groups().delete("grp_old", false, moderatorId, WriteOptions.none().withIfMatch(old.version()));
```

| Call | Notes |
|------|-------|
| `update(groupId, UpdateGroupInput, opts)` | Sends only the fields set on the builder. `actorUserId` is not a change on its own: `build()` throws `IllegalStateException` when it is the only field. A passcode is set with `passcode(...)` and cleared with `passcode(null)`. |
| `delete(groupId, hard, actorUserId, opts)` | A soft delete can be undone with `restore` within the server's retention window and is idempotent; `hard = true` removes the group and everything in it. `delete(groupId)` is a soft delete with no actor. |
| `restore(groupId, opts)` | Idempotent for a group that is not deleted; fails with `restore_window_expired` after the window. |
| `inviteByUserId(groupId, userId, roleId, opts)`, `inviteByCode(groupId, roleId, expiresIn, opts)` | `expiresIn` is a positive integer followed by `s`, `m`, `h` or `d`, or null for no expiry. |
| `acceptInvitation(code, userId, opts)`, `declineInvitation(code, userId, opts)` | The declining user may be null. |
| `join(groupId, userId, passcode, opts)`, `leave(groupId, userId, opts)` | Only a `public` group admits an open join; a group with a passcode needs the right one. |
| `kick(groupId, userId, reason, actorUserId, opts)` | The actor is carried as `kickedBy` on the `member.left` event. The older `kick(groupId, userId, reason, opts)` sends no actor. |
| `banHistory(groupId, PageOptions)` | Every set and lift of a ban in the group, newest first, as `BanHistoryEntry` records. |
| `setRelationship(a, b, type, mutual, actorUserId, opts)`, `clearRelationship(a, b, mutual, actorUserId, opts)` | The actor becomes the relationship's `setBy`. `getRelationship(a, b)` returns an `Optional`; `listRelationships(groupId)` lists the group's A side. |
| `setParent(groupId, parentGroupId, opts)`, `listChildren(groupId)` | A null parent makes the group top-level; a cycle fails with `parent_cycle`. |
| `invitations().list(groupId, ListInvitationsOptions)` | Used and expired invitations are left out unless the options include them. |

`Group.version()` is the group's [version](/api-reference/groups#group-versions), a decimal string. Groups returned by `get`, `create`, `update` and `restore` carry it; groups from lists, `setParent`, `listChildren` and events have it null, as do groups from servers older than the field. Pass it to `withIfMatch` for `update` and `delete`: a group changed since fails with `412 precondition_failed`, and `details()` holds the current `version`. A null version sends no `If-Match`, so check for one before relying on the guard. Every `actorUserId` parameter may be null.

### Group batches

`groups().batch(groupId, ops, opts)` applies up to 50 (`GroupBatchOp.MAX_OPS`) writes to one group in order, in one transaction: all of them or none. Each op is the write of one single-group call, built with a `GroupBatchOp` factory, and sees the effects of the ops before it. `withIfMatch(group.version())` makes the whole batch conditional on the group's version. The server rules are in [`POST /v1/groups/:id/batch`](/api-reference/groups#post-v1groupsidbatch).

| Factory | Single call |
|---------|-------------|
| `memberAdd(userId)`, `memberAdd(userId, roleId, actorUserId, createOnly)` | `members().add`; `createOnly` is the batch form of `withIfNoneMatchAny()` |
| `memberKick(userId, reason, actorUserId)` | `groups().kick` |
| `memberLeave(userId)` | `groups().leave` |
| `memberBan(userId, reason, expiresAt, actorUserId)` | `groups().ban` (null `expiresAt`: permanent) |
| `memberUnban(userId, actorUserId)` | `groups().unban` |
| `memberMetadata(userId, metadata)`, `memberNotes(userId, SetMemberNotesInput)` | `members().setMetadata`, `members().setNotes` |
| `memberRoleAdd(userId, roleId, actorUserId)`, `memberRoleRemove(userId, roleId, actorUserId)` | `members().assignRole`, `members().removeRole` |
| `groupUpdate(UpdateGroupInput)` | `groups().update`, without a passcode (throws `IllegalArgumentException` if the input sets one) |
| `roleEntrySet(roleId, PermissionEntry)`, `roleEntryRemove(roleId, permission, context)` | `roles().grantPermission`, `roles().revokePermission`, for a role of this group; a null context is global |
| `relationshipSet(otherGroupId, type, mutual, actorUserId)`, `relationshipClear(otherGroupId, mutual, actorUserId)` | `groups().setRelationship`, `groups().clearRelationship` from this group |

Nullable arguments (reasons, actors, roles) may be null; required ids throw `NullPointerException` when null, and `batch` throws `IllegalArgumentException` for an empty list or more than 50 ops.

The answer is a `GroupBatchResponse`: `version()` is the group's version after the batch, and `results()` (or `result(i)`) holds one `GroupBatchResult` per op, describing the state right after that op. Read it with `asMember()`, `asGroup()` (a group without a version), `asRole()` or `asRelationship()`, each an `Optional` that is empty when the op answered something else; `relationshipClear` answers `GroupBatchResult.NONE`. The results are a sealed hierarchy (`MemberResult`, `GroupResult`, `RoleResult`, `RelationshipResult`, `Empty`), so a `switch` over them works too.

A failing op fails the whole batch with that op's own error, and `JunjoException.opIndex()` names it; it is empty for a failure of the batch as a whole, such as a stale `If-Match`. Handing a group's top role from one member to another, with a retry when the group changed in between:

```java
boolean handOver(String groupId, String from, String to, String leaderRole, String officerRole) {
    for (int attempt = 0; attempt < 3; attempt++) {
        Group group = junjo.groups().get(groupId).join().orElseThrow();
        Member current = junjo.members().get(groupId, from).join().orElse(null);
        if (current == null || !current.roles().contains(leaderRole)) return false;   // nothing to hand over

        List<GroupBatchOp> ops = List.of(
                GroupBatchOp.memberRoleRemove(from, leaderRole, null),
                GroupBatchOp.memberRoleAdd(to, leaderRole, null),
                GroupBatchOp.memberRoleAdd(from, officerRole, null));
        try {
            GroupBatchResponse done = junjo.groups().batch(groupId, ops,
                    WriteOptions.idempotent().withIfMatch(group.version())).join();
            done.result(1).asMember().ifPresent(m -> log.info("new leader at version " + m.version()));
            return true;
        } catch (CompletionException e) {
            if (!(e.getCause() instanceof JunjoException je)
                    || !"precondition_failed".equals(je.code())
                    || je.opIndex().isPresent()) {
                throw e;
            }
            // The group changed since the read: read again and decide again.
        }
    }
    return false;
}
```

## Safe writes

Every write takes an optional `WriteOptions`:

```java
// Idempotency-Key: a repeat within 24 hours returns the first result instead of writing again.
junjo.bans().add(CreateBanInput.builder(player).reason("cheating").build(), WriteOptions.idempotent());

// If-Match: refused with 412 precondition_failed when the member changed since it was read.
Member m = junjo.members().get("grp_main", player).join().orElseThrow();
junjo.members().assignRole("grp_main", player, "role_mod", moderatorId,
        WriteOptions.idempotent().withIfMatch(m.version()));
```

`Member.version` and `MemberAccess.version` are the member version; `Ban.version` and `Sanction.version` are the person's moderation version, which bans and sanctions share. `bans().moderation(userId)` reads it for a person with nothing active; an id the game has never seen reads as version 0. `Group.version()` is the group version, a decimal string that `withIfMatch(String)` sends as it is (see [Groups](#groups)).

### Write tags

A write tag labels the writes of one writer, so it can recognise the events they cause (see [Event origin](#event-origin)). Set one for the whole client, or per write:

```java
JunjoClient junjo = JunjoClient.builder()
        .baseUrl("https://api.junjo.io")
        .apiKey(System.getenv("JUNJO_API_KEY"))
        .writeTag("server-1")          // sent as Junjo-Write-Tag on every request
        .build();

junjo.groups().update("grp_main", input, WriteOptions.idempotent().withWriteTag("server-1-admin"));
```

A tag is 1 to 128 (`WriteOptions.WRITE_TAG_MAX_LENGTH`) printable ASCII characters without spaces; the builder, `withWriteTag` and the `WriteOptions` constructor throw `IllegalArgumentException` for anything else. `withWriteTag(null)` falls back to the client-level tag. A [`WriteQueue`](#writequeue) sends its client's tag on every queued write; `QueuedWrite` has no tag of its own. See [Write tags](/api-reference#write-tags).

### Create-only adds

By default `members().add` merges into an existing membership: an active member who lacks the role gains it, and a left or kicked member is reactivated. `withIfNoneMatchAny()` sends `If-None-Match: *`, so the add applies only when the player has no membership row in the group in any status, and is otherwise refused with `412 precondition_failed` having written nothing:

```java
try {
    junjo.members().add("grp_main", player, "role_member", null,
            WriteOptions.idempotent().withIfNoneMatchAny()).join();
} catch (CompletionException e) {
    if (e.getCause() instanceof JunjoException je && "precondition_failed".equals(je.code())) {
        // Already in the group; je.details() holds memberStatus. Nothing was changed.
    } else {
        throw e;
    }
}
```

The check runs inside the server's transaction, so unlike a `get` followed by `add` it cannot race with a promotion, join or add of the same player. A ban is still reported as `banned` first. See [Create-only adds](/api-reference/groups#create-only-adds).

## Local permission checks

```java
RoleGraph graph = junjo.roles().getGraph("grp_main").join().value();
MemberAccess access = junjo.members().getAccess("grp_main", player).join().value();

PermissionResolver.GroupResolver resolver = PermissionResolver.compile(graph);
PermissionCheckResult result = resolver.check(access, "chat.color");
```

The resolver implements the [layered precedence](/api-reference/permissions): the member's overrides, then directly held roles, then their parents; within the deciding layer, the best [context](#contexts) match, then the most specific key; deny on ties. Both [permission modes](/api-reference/permissions#permission-modes) are supported. In `nodes` mode, case folding is ASCII-only, exactly like the server, so the answer never depends on the JVM's default locale. A member whose status is not `active` answers `allowed=false, source=none`, as on the server.

## Contexts

An entry or an override can carry a [context](/api-reference/permissions#contexts), such as the world a player is in, so it applies only to checks made in that context. A `Context` is an immutable map of context keys to values; values are folded with the server's ASCII-only lowercase fold, so `Context.of("world", "World_Nether")` equals `Context.of("world", "world_nether")`. `Context.GLOBAL` is the empty context. Every call that takes a context has an overload without one, which means global.

```java
Context creative = Context.of("world", "creative");

// Writes: an entry's identity is its key and its context.
junjo.roles().setEntries(roleId, List.of(
        PermissionEntry.deny("essentials.fly"),                 // global
        PermissionEntry.grant("essentials.*", creative)));      // only in creative
junjo.roles().grantPermission(roleId, "worldedit.*", true, creative);
junjo.roles().revokePermission(roleId, "worldedit.*", creative);    // ?context.world=creative
junjo.members().overridePermission("grp_main", player, "chat.color", false, Context.of("world", "hub"));
junjo.members().clearPermissionOverride("grp_main", player, "chat.color", Context.of("world", "hub"));
queue.enqueue(QueuedWrite.overridePermission("grp_main", player, "fly", false, creative));

// Server checks, and the deciding entry's context.
PermissionCheckResult r = junjo.permissions().check(player, "grp_main", "essentials.fly", creative).join();
r.context();   // {"world":"creative"}, or Context.GLOBAL when a global entry decided
junjo.permissions().checkBatch(List.of(
        new PermissionCheckRequest(player, "grp_main", "essentials.fly", creative)));
```

`PermissionEntry.context()`, `MemberPermissionOverride.context()` and `PermissionCheckResult.context()` are never null; `ImportMember.overrides` takes contextual entries too, and `ExportRecord.context(element)` reads the `context` of one exported role entry or member override. How a contextual entry ranks against a global one, and against a more specific key, is described under [Precedence](/api-reference/permissions#precedence).

### Inheritance in the mirror

A game can declare that one value inherits another's entries, in its config's [`permissions.contexts`](/api-reference/admin#permission-contexts). The config is set through the admin API and is readable with the game's own key:

```java
PermissionConfig config = junjo.permissions().config().join();
config.mode();       // PermissionMode.EXACT or NODES
config.contexts();   // the ContextInheritance, values folded

RoleGraph graph = junjo.roles().getGraph("grp_main").join().value();
graph.contexts();    // the same inheritance, carried by every role graph
PermissionResolver.compile(graph, graph.contexts()).check(access, "warp.spawn", Context.of("world", "pvpworld"));
```

The mirror needs no table from you. It takes the inheritance from the server: every role graph it loads carries it, so the newest load sets it, and a `permissions.config.updated` event on the game stream replaces it live. When that event also changes the permission mode, the mirror reloads the role graphs it holds. Each change of the inheritance checks resolve with is reported to `onChange` as a `ROLE_GRAPH` change with null ids, and checkers taken before it follow it. The snapshot file keeps the server's value, so a mirror restarted while the server is unreachable still answers with the right inheritance.

```java
GameMirror mirror = GameMirror.builder(junjo).group("grp_main").build();
mirror.can(player, "grp_main", "warp.spawn", Context.of("world", "pvpworld"));
mirror.contextInheritance();         // what checks resolve with
mirror.serverContextInheritance();   // what the server last sent
```

With a server whose role graphs do not carry the inheritance yet, the mirror reads none, and you can give it the same table as the game's config. Such a table is an explicit override: it wins over whatever the server sends, so keep it identical to the game's config, or contextual answers can differ from `permissions().check`.

```java
ContextInheritance worlds = ContextInheritance.builder()
        .inherit("world", "pvpworld", "world")
        .inherit("world", "world_nether", "world")
        .inherit("world", "cave_world_nether", "world_nether")
        .build();   // refuses a cycle, a chain over 16 steps and the other limits the server refuses

GameMirror legacy = GameMirror.builder(junjo).group("grp_main").contextInheritance(worlds).build();
legacy.setContextInheritance(next);   // replace the override; null follows the server again
```

`ContextInheritance.of(map)` reads the config's `{ key: { value: [parents] } }` shape.

### Per-world checks on a Paper server

A Paper server keeps one context-bound `MemberChecker` per player and replaces it when the player changes world. The checker caches the member's compiled overrides, role layers and the world's inheritance chain, memoizes its answers, and always reads the mirror's current state:

```java
private final Map<UUID, MemberChecker> checkers = new ConcurrentHashMap<>();

private void bind(Player player) {
    String id = Ids.namespaced("mc", player.getUniqueId());
    checkers.put(player.getUniqueId(),
            mirror.checker(id, "grp_server", Context.of("world", player.getWorld().getName())));
}

@EventHandler
public void onJoin(PlayerJoinEvent event) {
    bind(event.getPlayer());
}

@EventHandler
public void onWorldChange(PlayerChangedWorldEvent event) {
    bind(event.getPlayer());
}

@EventHandler
public void onQuit(PlayerQuitEvent event) {
    checkers.remove(event.getPlayer().getUniqueId());
}

boolean has(Player player, String permission) {
    MemberChecker c = checkers.get(player.getUniqueId());
    return c != null && c.can(permission) == Answer.YES;   // lock-free, no I/O
}
```

World names such as `w_TheNewIsland` can be passed as they are: the fold makes them match entries written as `w_thenewisland`.

## The game stream

```java
String position = junjo.events().position().join();
// ... load your snapshot here ...

GameSubscription sub = junjo.events().subscribe(
        (event, pos) -> {
            switch (event) {
                case JunjoEvent.GameUserBanned b -> kickIfOnline(b.userId());
                case JunjoEvent.RoleUpdated u -> reloadRoles(u.groupId());
                default -> { }
            }
        },
        SubscribeOptions.builder()
                .from(position)
                .types(EventType.GAME_USER_BANNED, EventType.ROLE_UPDATED)
                .onResync(newPosition -> reloadSnapshot())
                .onError(err -> log.error("game stream stopped", err))
                .build()).join();
```

Events are a sealed `JunjoEvent` hierarchy of records; `type()` returns the `EventType` constant, whose `wire()` is the server's spelling. They are delivered in position order on the stream's own thread. Behaviour matches the TypeScript SDK's `junjo.events.subscribe`:

- The first connection's failure fails the returned future and is not retried.
- After that, when the server ends the stream (deploys, idle proxies), it reconnects with `Last-Event-ID` set to the last position seen, with backoff and full jitter (1 s to 30 s by default). Heartbeats advance the position too.
- A connection that stays silent longer than `idleTimeout` (75 s; the server sends a heartbeat every 30 s) is dropped and resumed.
- `410 stream_position_expired` on a reconnect opens a live stream first and then calls `onResync` with the new position; reload your snapshot there. Without `onResync` it is fatal.
- Any other 4xx on a reconnect (`429 too_many_streams`, `401`) is fatal and reported once to `onError`.
- Unknown event types are skipped, but their position still counts, so a newer server cannot break an older client.

### Event origin

Every event carries `origin()`, a `JunjoEvent.EventOrigin(apiKeyId, tag)`: the id of the per-game key whose write caused the event (null for dashboard writes and for changes the server makes on its own) and that write's tag, or null. Events from servers older than the field read as `EventOrigin.NONE`, with both null. A writer that applies its own changes locally when they succeed can skip the events they cause:

```java
String myTag = "server-1";   // the client's writeTag
junjo.events().subscribe((event, pos) -> {
    if (myTag.equals(event.origin().tag())) return;   // this server made the change
    apply(event);
}, SubscribeOptions.builder().from(position).build());
```

Writers that share one key need different tags. See [Event origin](/api-reference/events#event-origin).

`GroupUpdated`, `GroupDeleted` and `GroupRelationshipChanged` carry `actorUserId()`, the user the write named as its actor, or null; `MemberLeft.kickedBy()` is set when a kick named an actor. On the game stream, the position of an event about a group is the [group version](/api-reference/groups#group-versions) it gave the group, so it compares with `Group.version()`.

## Sanctions

A [sanction](/api-reference/sanctions) is a game-wide restriction on a person, with a type your game defines (`mute`, `trade.lock`); at most one is active per person and type. Sanctions share the person's moderation version with game bans, so every write takes `If-Match` against it.

```java
Sanction mute = junjo.sanctions().add(
        AddSanctionInput.builder(player, "mute")
                .reason("spam")
                .expiresAt(Instant.now().plus(Duration.ofHours(1)))
                .actorUserId(moderatorId)
                .build(),
        WriteOptions.idempotent()).join();

junjo.sanctions().remove(player, "mute", moderatorId, WriteOptions.none().withIfMatch(mute.version()));

List<Sanction> active = junjo.sanctions().forUser(player).join().value();
Page<SanctionHistoryEntry> history = junjo.sanctions().history(player, null).join().value();
```

`bans().moderation(userId)` returns the active sanctions next to the game ban. Expiry is lazy, as with bans: no event fires when a sanction lapses, so check `Sanction.isActiveAt(now)`. A lift with nothing to lift fails with `not_found` for which `isNotActive()` is true (that answer wins over a stale `If-Match`). `AddSanctionInput` validates the type pattern locally and refuses the reserved type `ban`.

## Display names

Each id can carry a display name, set on exactly that id:

```java
junjo.identities().setDisplayName(player, "Steve");          // null clears it
List<DisplayNameMatch> hits = junjo.identities().findByName("steve", "mc").join();
```

`findByName` matches exactly, ignoring case, most recently named first, at most 20; the returned ids are the matching ids themselves. `Member.displayName()` and `MemberAccess.displayName()` carry the person-level name picked for your key, and `LinkedIdentity.displayName()` each id's own name. A change emits `identity.updated`.

## Export

The export needs a key with `canExport`; other keys fail with `permission_denied`. [`GET /v1/export`](/api-reference/export) streams the whole game as NDJSON. The SDK reads it line by line as it arrives and never holds the body:

```java
ExportSummary summary = junjo.export().read(record -> {
    switch (record.kind()) {
        case "person" -> backup.writePerson(record.json());
        case "group" -> backup.writeGroup(record.json());
        default -> { }
    }
}).join();
// summary.position(): replay the game stream from here to catch writes made during the export
```

To export only some record kinds, or only the groups of some kinds, pass `ExportOptions`:

```java
ExportOptions opts = ExportOptions.all()
        .withRecords(List.of("group", "role", "member"))
        .withGroupKinds(List.of("guild"));
junjo.export().read(opts, record -> backup.write(record.json())).join();
```

`records` names the kinds to export (never `game`, which is always sent with the header and end records); `groupKinds` keeps the group-scoped records (groups, roles, members, invitations, relationships by their A side, and the group rows of ban history and audit) of groups of those kinds only, and leaves game-scoped records alone. Null means no filter. `ExportOptions` throws `IllegalArgumentException` for an empty list or an entry that is empty or contains a comma; the server refuses an unknown kind with `bad_request`. Excluded kinds count 0 in the end record, and `group` records carry the group's `version`. See [Export](/api-reference/export).

`read` runs on its own daemon thread and hands records over in order, header and end included. `open()` returns a blocking `ExportReader` iterator instead. Either way the export fails with `invalid_wire_data` when the end record is missing (a cut-short export), when its counts disagree with the records read, or when the header is not format `junjo-export` version 1, and with `stream_overflow` when one line passes 16 Mi characters. Records already handed over stay handed over, so discard your output on any failure.

## GameMirror

`GameMirror` runs the [snapshot and stream pattern](/api-reference/events#snapshots-and-the-stream) for the state a game server checks on its hot path:

```java
GameMirror mirror = GameMirror.builder(junjo)
        .group("grp_main")
        .snapshotFile(dataDir.resolve("junjo-mirror.snapshot"))   // optional
        .onError(err -> log.warn("junjo mirror", err))
        .onChange(change -> refreshCaches(change))                  // on the applier thread
        .build();
mirror.start();                  // keeps retrying through an outage; isReady() turns true once loaded

mirror.track(player, "grp_main");              // loads the member's access asynchronously

// Lock-free, no I/O.
if (mirror.isBanned(player) == Answer.YES) disconnect(player);
Answer canBuild = mirror.can(player, "grp_main", "build.place");   // YES, NO or UNKNOWN
if (mirror.isSanctioned(player, "mute") == Answer.YES) blockChat(player);

mirror.untrack(player, "grp_main");
```

How it stays current, all on one applier thread in stream order:

| Event | Effect |
|-------|--------|
| `role.*`, `permission.*`, `group.updated` | Reload that group's role graph. |
| `member.*`, `role.changed` | Reload a tracked member's access, unless the event's `memberVersion` is not newer than the loaded version. |
| `game.user.banned`, `game.user.unbanned` | Update the ban map, unless the event's `moderationVersion` is not newer than the known one. |
| `game.user.sanctioned`, `game.user.unsanctioned` | Update the sanction map, unless the event's `moderationVersion` is not newer than the known one. Ban and sanction versions are tracked apart, because their snapshots are read at different moments. |
| `identity.linked`, `identity.unlinked` | Record the person's ids, and reload the bans, sanctions and tracked memberships of every id involved. |
| `identity.updated` | Reload the tracked memberships of the person, which carry its display name. |
| `permissions.config.updated` | Apply the event's context inheritance to every held role graph, and reload the graphs when the event changes the permission mode. |
| `410` on reconnect | Reload everything at the new position. |

What else to know:

- **Linked ids.** A person may hold several linked ids; the server names them by one rendered id. The mirror records each person's ids, so `isBanned`, the sanction reads, `check` and `track` answer for the person whatever id you pass. An id the mirror has not resolved yet answers `UNKNOWN` for bans and sanctions (unless that exact id is banned or sanctioned) and resolves in the background; call `resolve(id)` or `track` to resolve it first. `resolve` returns the id the mirror keys the person by.
- **Answers.** `UNKNOWN` (or an empty `Optional`) means the state needed is not loaded yet. Sanction and ban expiry is judged against the mirror's clock, because the server emits nothing when one lapses.
- **Changes.** `onChange` receives a `MirrorChange(kind, userId, groupId)` after each change is readable: `ACCESS`, `BAN`, `SANCTION`, `ROLE_GRAPH` or `DISPLAY_NAME`. A full load reports one change per kind with null ids. It runs on the applier thread and must not block; a throwing listener is logged and ignored.
- **Outages.** A failed load keeps the previous state, reports to `onError` and retries with backoff. That includes `start()`: its future completes once the mirror is ready and never fails because the server is down.
- **Snapshot file.** With `snapshotFile`, the mirror saves its state (position, role graphs, bans, sanctions, tracked members, resolved ids, the server's context inheritance) at most every `snapshotInterval` (30 s) and on `close()`, using a temporary file, `fsync`, an atomic move and a CRC32 checksum. At start it loads the file and answers from it at once, then resumes the game stream from the saved position. **Data loaded from the file may be stale until the stream catches up.** When the saved position has expired, the mirror reloads everything from the server; an unreadable file is ignored and reported.
- **Batched member loads.** `track` calls issued close together are loaded with one `getAccessMany` request per group (up to 100 ids). Member loads have their own timeout, `memberLoadTimeout` (5 s), separate from `loadTimeout` (60 s) for the bulk loads.
- **Bursts.** The reloads events ask for wait while more events are queued behind them (at most 50 ms, or 100 members), so a mass role change reloads each role graph once and reads the affected tracked members with batched `getAccessMany` requests instead of one request per event. They run before anything that is not an event, so `sync()` and `track` see them applied, and `position()` only moves past an event once its reloads are in. A burst of changes to one graph is reported to `onChange` once.
- **Non-members.** A user with no membership in a group answers `source=none`, as `permissions().check` does. `defaultRoleForNonMembers(true)` checks such users against the group's default role instead; that is off by default because it then differs from the server's answer.
- **Retained members.** `retainUntracked(window)` keeps an untracked member's last loaded access, in memory and in the snapshot file, for that window after they were last tracked; each entry records `lastConnectedAt`. Tracking the member again within the window answers from the retained access at once, even when the server is unreachable, and the access is reloaded as for any track; when the reload succeeds the fresh access replaces it and is reported as an `ACCESS` change. The `track` future completes once that reload has succeeded or failed (a failure goes to `onError` and is retried). A retained member is not tracked: its reads answer `UNKNOWN`, it is not in `trackedMembers`, and stream events never reload it. An entry is dropped when it outlives the window (pruned at start and periodically), when a member event carries a newer `memberVersion` or none, when an identity event names one of the person's ids, when its group is deleted, and on a full reload after an expired position. Off by default; snapshot files written without retained members still load.
- **Repeated checks.** `check` and `can` prepare each tracked member's checks once per context (overrides, role layers and inheritance chains) and memoize up to 256 answers, so a repeated check is a map lookup with no allocation. The prepared form is bound to the loaded access and role graph, and is rebuilt when either is reloaded, so it never answers from stale state. `mirror.checker(userId, groupId)` returns a `MemberChecker` that gives the same answers with its own memo; `grantedKeys()` lists the keys that resolve to allowed. `mirror.checker(userId, groupId, context)` binds the checker to a [context](#contexts).
- **Ignoring roles.** `checker.excludingRoles(roleIds)` returns a checker for the same member and context that answers as if the member did not hold those roles, for example to stop staff roles counting while Junjo has been unreachable for a long time. Exclusion removes the roles from the member's held roles and nothing else, so the answer is what `permissions().check` would give with those roles unassigned: overrides and contexts apply as before, and an excluded role that is a parent of a role still held keeps applying through that role. Exclude the child roles too to cut it off. Exclusions accumulate when chained; `excludedRoles()` lists them.
- **Ignoring overrides.** `checker.excludingOverrides()` returns a checker for the same member and context that answers as if the member had no personal overrides, global or contextual. Role entries, role parents, the context and its inheritance apply as before, and so does the status gate: a member who is not active still answers `source=none`. It composes with `excludingRoles` in either order, the checker it came from is unchanged, and `grantedKeys()` leaves out the keys only the overrides named; `excludesOverrides()` tells whether a checker ignores them.
- **Contexts.** `check`, `can` and `checker` take an optional `Context`; without one only global entries apply. Contextual entries and overrides reload with their role graph and member access, on `role.updated` and `member.updated`. The inheritance comes from the server, unless `contextInheritance(...)` overrides it (see [Inheritance in the mirror](#inheritance-in-the-mirror)).
- **Reads.** `bans()`, `sanctions(userId)`, `sanctionsAll()`, `trackedMembers(groupId)`, `access(userId, groupId)` (metadata included), and stream health: `streamState()`, `isLive()`, `lastEventAt()`, `position()`.

## WriteQueue

`WriteQueue` keeps writes on disk until the server has answered them:

```java
WriteQueue queue = WriteQueue.builder(junjo, dataDir.resolve("junjo-writes.jsonl"))
        .onConflict(o -> log.warn("stale write dropped: " + o.entry().write().label()))
        .onRejected(o -> log.warn("write refused: " + o.error().code()))
        .open();

queue.enqueue(QueuedWrite.assignRole("grp_main", player, "role_vip", moderatorId).ifMatch(memberVersion));
queue.enqueue(QueuedWrite.removeBan(player, moderatorId));
queue.enqueue(QueuedWrite.removeSanction(player, "mute", moderatorId));
queue.enqueue(QueuedWrite.addMemberIfAbsent("grp_main", player, "role_member", null));

queue.close();   // drains for up to closeTimeout (10 s); the rest is resent on the next open()
```

The `QueuedWrite` factories are named after the API calls and send exactly the same requests: `addMember`, `assignRole`, `removeRole`, `overridePermission`, `clearPermissionOverride`, `setMetadata`, `setNotes`, `kick` (with an optional actor: `kick(groupId, userId, reason, actorUserId)`), `groupBan`, `groupUnban`, `addBan`, `removeBan`, `addSanction`, `removeSanction`, plus `groupBatch(groupId, ops)` for a [group batch](#group-batches) and `custom` for any other route. `addMemberIfAbsent` is `addMember` with `If-None-Match: *` (the queued form of `withIfNoneMatchAny()`), and `ifNoneMatchAny()` adds the same header to any queued write.

- **Durable.** `enqueue` returns after the entry is appended to the journal and forced to disk; when the force fails, `enqueue` throws and the entry is not queued. Concurrent `enqueue` calls share forces, and the force runs outside the queue's lock. A success's `done` record is not forced on its own (the next force or `close()` writes it); if a crash loses it, the entry is resent with its idempotency key. Every journal line carries a CRC32. On open the journal is replayed and compacted through a temporary file, an atomic move and a directory `fsync`; when the file system cannot move atomically, the old journal is kept and an ERROR is logged.
- **Dead letters.** Every entry the server refuses (`412` or another 4xx) is appended, with the status and the raw response body, to the dead-letter file next to the journal (`deadLetterFile()`, the journal's name plus `.dead`) before any callback runs. A journal line that fails its checksum, or the torn last line of a crashed append, is moved there too, with a reason.
- **Replay-safe.** Each entry carries a random `Idempotency-Key` for its whole life, across retries and restarts. Add `ifMatch(version)` so a write is refused, not applied, if the state changed after you decided it; that also covers replays older than the server's 24-hour key retention.
- **Ordered.** One drain thread sends entries in enqueue order. Network errors, timeouts, 5xx, 408, 429, 409 `idempotency_key_in_progress` and 401 retry the head entry with backoff (401 is kept so a rotated key does not wipe the queue).
- **Outcomes.** 2xx calls `onSuccess`. `412 precondition_failed` drops the entry and calls `onConflict`; for `addMemberIfAbsent` that means the player already had a membership, which was left untouched. Any other 4xx drops it and calls `onRejected`.
- **Batches.** A queued `groupBatch` keeps one idempotency key for its whole life, like every entry, and applies all of its ops or none, so a replay cannot apply part of it twice. With `ifMatch(group.version())`, a batch on a group that changed in the meantime is refused with `412` and goes to `onConflict`; it is not retried. A failing op is a rejection (`onRejected`), and the error's `opIndex()` names the op.
- **Lifts that find nothing to lift succeed.** A queued lift (`removeBan`, `groupUnban`, `removeSanction`) answered with `isNotActive()` counts as success. A `not_found` without that reason (an unknown group) is still a rejection.

## Ids

```java
Ids.namespaced("mc", uuid);                         // "mc:2f0c1a3b-4d5e-6f70-8192-a3b4c5d6e7f8"
Ids.canonicalize("mc:2F0C1A3B4D5E6F708192A3B4C5D6E7F8");
```

When a game [declares a canonical format](/api-reference/identity#canonical-formats) for a namespace, the server rejects every other spelling of an id; `Ids.namespaced` always produces the canonical lowercase, hyphenated form.

## Example: a Minecraft server plugin

This example shows one way to wire the SDK into a Paper plugin: players are `mc:` ids built from their UUIDs, the game thread reads only from the mirror, and moderation writes go through the write queue so they survive a restart or an outage.

```java
public final class JunjoPlugin extends JavaPlugin implements Listener {
    private JunjoClient junjo;
    private GameMirror mirror;
    private WriteQueue queue;

    @Override
    public void onEnable() {
        junjo = JunjoClient.builder()
                .baseUrl("https://api.junjo.io")
                .apiKey(System.getenv("JUNJO_API_KEY"))
                .build();
        mirror = GameMirror.builder(junjo)
                .group("grp_server")
                .snapshotFile(getDataFolder().toPath().resolve("junjo-mirror.snapshot"))
                .onError(err -> getLogger().warning("junjo: " + err.getMessage()))
                .build();
        mirror.start();   // answers from the snapshot file at once if there is one
        try {
            queue = WriteQueue.builder(junjo, getDataFolder().toPath().resolve("junjo-writes.jsonl")).open();
        } catch (IOException e) {
            throw new IllegalStateException("cannot open the Junjo write queue", e);
        }
        getServer().getPluginManager().registerEvents(this, this);
    }

    @EventHandler
    public void onPreLogin(AsyncPlayerPreLoginEvent event) {
        // An async thread: waiting here is fine and resolves the player's linked ids.
        String id = Ids.namespaced("mc", event.getUniqueId());
        mirror.track(id, "grp_server").orTimeout(3, TimeUnit.SECONDS).exceptionally(err -> null).join();
        if (mirror.isBanned(id) == Answer.YES) {
            event.disallow(AsyncPlayerPreLoginEvent.Result.KICK_BANNED, Component.text("You are banned."));
        }
    }

    @EventHandler
    public void onChat(AsyncChatEvent event) {
        String id = Ids.namespaced("mc", event.getPlayer().getUniqueId());
        if (mirror.isSanctioned(id, "mute") == Answer.YES) event.setCancelled(true);
    }

    @EventHandler
    public void onPlace(BlockPlaceEvent event) {
        // The main thread: a lock-free read from memory, never a network call.
        String id = Ids.namespaced("mc", event.getPlayer().getUniqueId());
        if (!mirror.can(id, "grp_server", "build.place").orElse(false)) event.setCancelled(true);
    }

    @EventHandler
    public void onQuit(PlayerQuitEvent event) {
        mirror.untrack(Ids.namespaced("mc", event.getPlayer().getUniqueId()), "grp_server");
    }

    // Blocks for one fsync: call it from an async task, not the main thread.
    void mute(UUID player, UUID moderator, Duration length) throws IOException {
        queue.enqueue(QueuedWrite.addSanction(AddSanctionInput.builder(Ids.namespaced("mc", player), "mute")
                .expiresAt(Instant.now().plus(length))
                .actorUserId(Ids.namespaced("mc", moderator))
                .build()));
    }

    @Override
    public void onDisable() {
        queue.close();    // what is left is resent on the next start
        mirror.close();   // saves the snapshot file
        junjo.close();
    }
}
```

## Thread guarantees

- `JunjoClient` is safe for concurrent use. Future completions run on the client's executor (a cached pool of daemon threads unless you supply one); do not block in them.
- Stream events arrive on the subscription's own daemon thread, one at a time.
- `GameMirror` reads never block and never do I/O; its writes, and its callbacks, happen on one applier thread.
- `WriteQueue.enqueue` blocks for the journal append and one `fsync`, typically a few milliseconds and more on a slow disk, so call it from an async task rather than the main thread. Its callbacks run on the drain thread.
- Every SDK thread is a daemon, so a forgotten `close()` never keeps the JVM alive.

## Shading

The SDK loads no classes by name, uses no `ServiceLoader` and reads no resources by path, so it can be relocated with Shadow or Maven Shade. Relocate Gson with it if the host platform ships its own Gson, and leave the SDK's `module-info.class` out of the shaded jar: it names the original packages, which no longer exist after relocation.

```kotlin
tasks.shadowJar {
    relocate("io.junjo.sdk", "com.yourgame.libs.junjo")
    relocate("com.google.gson", "com.yourgame.libs.gson")
    exclude("module-info.class")
}
```

With Maven Shade, add a filter that excludes `module-info.class` for the `io.junjo:junjo-sdk` artifact. Only the API packages are exported from the module; `io.junjo.sdk.internal` is not supported API.
