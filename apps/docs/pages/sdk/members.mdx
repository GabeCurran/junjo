# `junjo.members`

The members namespace operates on `Member` rows: a member is one user's relationship to one group. The same external user id can be a member of many groups within the same game; each membership is a separate `Member` row.

Every `Member` carries a `version`: 1 when the row is created, one higher after every write that changes it. [`getAccess`](#getaccessgroupid-userid) returns the same version. Every write here accepts `idempotencyKey`, and the member-scoped writes (`setMetadata`, `setNotes`, `assignRole`, `removeRole`, `overridePermission`, `clearPermissionOverride`) also accept `ifMatch`, the version the write expects. A stale version rejects with `precondition_failed` and changes nothing; a missing member rejects with `not_found`. See [Safe writes](/sdk#safe-writes).

Members also carry the person's `displayName` (`string | null`), picked by the [display name rule](/sdk/identities#display-names). It is on member reads and write responses and on `MemberAccess`. The `member` snapshot inside a `member.joined` event has no `displayName` field at all, so treat `undefined` as "not sent" rather than "no name".

```ts
const member = await junjo.members.get(groupId, userId);
if (member) {
  await junjo.members.assignRole(groupId, userId, officerRoleId, {
    ifMatch: member.version,
    idempotencyKey: crypto.randomUUID(),
  });
}
```

## `add(groupId, userId, opts?)`

Adds a user to a group directly: the server-to-server counterpart to `groups.join`. Returns the `Member`.

```ts
await junjo.members.add(groupId, "user_alice" as UserId, { roleId: officerRoleId });
```

Unlike `join`, this **ignores the group's `visibility`**, so provisioning does not have to make internal authorization groups publicly joinable to populate them. That was the workaround the route exists to remove; see [Provisioning an existing app](/provisioning).

What it does:

- Creates the user's Junjo identity on demand, so the user does not have to exist yet.
- Assigns `opts.roleId` in the **same transaction** as the membership, replacing the join-then-`assignRole` two-step and removing the window where a failed second call leaves a member role-less. The role must belong to this group.
- Reactivates a member who `left` or was `kicked`, keeping their original `joinedAt`.
- Is idempotent: re-adding an active member returns them unchanged, so a provisioning script is safe to re-run.

What it does not do: bypass bans. A game ban or group ban still refuses with `banned`, because a ban is state your game set deliberately. An expired timed ban does not block the add.

### Options

| Field | Type | Notes |
|-------|------|-------|
| `roleId` | `RoleId` | Assigned in the same transaction. Must belong to `groupId`. |
| `actorUserId` | `UserId` | External id of the acting moderator, recorded on the audit entries. |

### Events

Only an actual transition emits anything, so a re-run is silent: becoming active writes a `member.joined` audit entry tagged `via: "admin-add"` and emits `member.joined`; a newly assigned role writes `role.assigned` and emits `role.changed`.

### Errors

| Code | Status | When |
|------|--------|------|
| `bad_request` | 400 | Empty `userId`. |
| `role_group_mismatch` | 400 | `roleId` belongs to another group. No member is created. |
| `not_found` | 404 | Group, or the supplied `roleId`, not found in the calling game. |
| `banned` | 403 | The user is banned game-wide or from this group. |
| `invalid_api_key` | 401 | API key missing, malformed, or revoked. |

### See also

- [`POST /v1/groups/:id/members`](/api-reference/groups) - the underlying HTTP route, including the `200` versus `201` split.

## `import(groupId, input, opts?)`

Imports up to 500 memberships into one group, with their roles, overrides and metadata, in one transaction: every row applies or none does. Built for moving an existing permission setup into Junjo. Like [`add`](#addgroupid-userid-opts) it ignores the group's `visibility`.

```ts
import { JunjoError, memberImportErrors } from "@junjo.io/sdk";

try {
  const result = await junjo.members.import(
    groupId,
    {
      members: [
        {
          userId: "mc:0f8fad5b-d9cb-469f-a165-70867728950e" as UserId,
          roleIds: [vipRoleId],
          overrides: [{ permission: "fly" as PermissionKey, value: true }],
          metadata: { prefix: "[VIP]" },
        },
        { userId: "mc:7c9e6679-7425-40de-944b-e07fc1f90ae7" as UserId },
      ],
    },
    { idempotencyKey: "import-2026-11-06-batch-1" },
  );
  result.created;  // members created
  result.items;    // [{ userId, status, version }], in input order
} catch (e) {
  for (const row of memberImportErrors(e)) {
    console.warn(`row ${row.index} (${row.userId}): ${row.code} ${row.message}`);
  }
  throw e;
}
```

Each row ensures an active membership: a new member is created, and a `left`, `kicked` or `invited` one is reactivated. A field that is present replaces the member's current value; a field that is absent is left as it is. The import never assigns the group's `defaultRoleId`: a created member holds only the roles in `roleIds`. Override entries use the role-entry shape, `{ permission, value }`.

Re-running an identical import reports every row `unchanged` and writes nothing, so a failed import can be retried.

### Input

| Field | Type | Notes |
|-------|------|-------|
| `members` | `MemberImportRow[]` | 1 to 500 rows with unique `userId`s. Each row: `userId`, and optional `roleIds`, `overrides`, `metadata`. |
| `allowBanned` | `boolean` | Default `false`: a person banned from the game or the group fails their row with `banned`. `true` imports their roles, entries and metadata without changing any ban. |
| `actorUserId` | `UserId` | External id of the acting moderator, recorded on the audit entries. |

### Returns

`MemberImportResult`: `{ created, reactivated, updated, unchanged, items }`. Each item is `{ userId, status, version }`, where `status` is `"created"`, `"reactivated"`, `"updated"` or `"unchanged"` and `version` is the member's version after the call.

### Events

The same events the equivalent single calls emit (`member.joined`, `role.changed`, `member.updated`), for members the import changed. The events for one member share a `memberVersion` ([versions on events](/sdk/events#versions-on-events)). Unchanged rows emit nothing.

### Errors

| Code | Status | When |
|------|--------|------|
| `bad_request` | 400 | The body is malformed, or one or more rows failed validation. `memberImportErrors(err)` lists every failing row as `{ index, userId, code, message }`, with `code` one of `banned`, `invalid_user_id`, `bad_request`, `not_found`. |
| `banned` | 403 | Every failing row is a ban. The rows are listed the same way. |
| `not_found` | 404 | Group not found in the calling game. |
| `invalid_api_key` | 401 | API key missing, malformed, or revoked. |

### See also

- [`POST /v1/groups/:id/members/import`](/api-reference/groups#post-v1groupsidmembersimport) - the underlying HTTP route.

## `get(groupId, userId)`

Fetches a single member by the dev's external user id within a group. Returns `Member | null`: the SDK turns the server's `404 not_found` response into `null` so callers can branch on `if (member)` without a try/catch. Other errors throw `JunjoError`.

```ts
const member = await junjo.members.get("grp_xyz" as GroupId, "user_alice" as UserId);
if (!member) {
  // not in this group (or the group is soft-deleted, or cross-game)
  return;
}
member.status; // "active" | "invited" | "left" | "kicked" | "banned"
```

The response includes members in any status; historical rows (`left`, `kicked`) are returned as well as active members.

### Errors

| Code | Status | When |
|------|--------|------|
| `invalid_api_key` | 401 | API key missing, malformed, or revoked. Thrown. |

`404 not_found` is converted to `null`; it is not thrown.

### See also

- [`GET /v1/groups/:id/members/:userId`](/api-reference/groups) - the underlying HTTP route.

## `list(groupId, opts?)`

Returns a single page of members in a group, sorted by `joinedAt` descending. Pagination is cursor-based; pass the `nextCursor` from the previous page to fetch the next.

```ts
let cursor: string | null | undefined;
do {
  const page = await junjo.members.list("grp_xyz" as GroupId, {
    limit: 50,
    cursor: cursor ?? undefined,
  });
  for (const member of page.items) {
    console.log(member.userId, member.status);
  }
  cursor = page.nextCursor;
} while (cursor);
```

Defaults to returning members in every status (`active`, `invited`, `left`, `kicked`, `banned`). Pass `status: ["active"]` to filter server-side.

### Options

| Field | Type | Default | Notes |
|-------|------|---------|-------|
| `limit` | number | `50` | 1-100 inclusive. |
| `cursor` | string | undefined | The `nextCursor` from a previous `list` call. |
| `status` | `MemberStatus[]` | `undefined` (all) | Server-side filter. Common shapes: `["active"]` for current members, `["banned"]` for the moderation panel, `["active","invited"]` for "reachable" rows. Sent to the server as a comma-separated query param. |

### Returns

`Page<Member>`:

| Field | Type | Notes |
|-------|------|-------|
| `items` | `Member[]` | Up to `limit` members, ordered by `joinedAt` desc with `id` desc as a tiebreaker. |
| `nextCursor` | string \| null | The id of the last item, or `null` if this is the last page. |

### Errors

| Code | Status | When |
|------|--------|------|
| `bad_request` | 400 | `limit` out of range, or `cursor` does not point at a member of this group. |
| `not_found` | 404 | No group with that id in the calling game (soft-deleted and cross-game collapse here). |
| `invalid_api_key` | 401 | API key missing, malformed, or revoked. |

### See also

- [`GET /v1/groups/:id/members`](/api-reference/groups) - the underlying HTTP route.

## `listAll(groupId, opts?)`

Async-iterator wrapper over `list(...)`. Walks every page until `nextCursor` is `null`, yielding one `Member` at a time. Combine with `status` to iterate every banned member, every kicked member, etc., without managing cursors by hand.

```ts
for await (const m of junjo.members.listAll("grp_xyz" as GroupId, { status: ["banned"] })) {
  console.log(m.userId, m.bannedUntil);
}
```

Accepts the same options as `list` except `cursor` (the iterator manages cursors internally). Errors from the underlying `list` calls propagate out of the loop.

## `listForUser(userId, opts?)`

Returns every membership a user has within the calling game. Returns a bare `Member[]` (no pagination wrapper) capped at 1000 rows. A user with no `ExternalIdentity` for this game returns `[]`.

```ts
const memberships = await junjo.members.listForUser("user_alice" as UserId);
for (const m of memberships) {
  console.log(m.groupId, m.status);
}
```

### Options

| Field | Type | Default | Notes |
|-------|------|---------|-------|
| `gameId` | `GameId` | the calling game | Optional. Must equal the calling key's game; mismatches return `400`. Provided for forward-compatibility with cloud-only admin tooling. |

### Returns

`Member[]`. All rows carry the same `userId` (the value supplied to `listForUser`). Soft-deleted groups are excluded.

### Errors

| Code | Status | When |
|------|--------|------|
| `bad_request` | 400 | `gameId` does not match the calling game. |
| `invalid_api_key` | 401 | API key missing, malformed, or revoked. |

### See also

## `setMetadata(groupId, userId, metadata)`

Replaces a member's metadata wholesale. The supplied object replaces whatever was stored; there is no deep merge. Returns the updated `Member`.

```ts
const updated = await junjo.members.setMetadata(
  "grp_xyz" as GroupId,
  "user_alice" as UserId,
  { rank: "officer", joinedRaid: "2026-04-01" },
);
```

The server treats every supplied metadata as a change (it does not deep-equal against the stored row, since jsonb does not reliably preserve key order). A PATCH that supplies the same metadata as the stored row still writes a `member.metadata.updated` audit entry. Pass an empty object (`{}`) to clear all keys.

Pass `{ ifMatch: member.version }` as a fourth argument to make the write conditional; the returned `Member` carries the new `version`.

### Errors

| Code | Status | When |
|------|--------|------|
| `not_found` | 404 | Group missing / soft-deleted / cross-game, or no `ExternalIdentity` for the user, or no `GroupMember` row in this group. Thrown. |
| `precondition_failed` | 412 | `opts.ifMatch` does not match the member's version. Nothing was written. |
| `invalid_api_key` | 401 | API key missing, malformed, or revoked. Thrown. |

### See also

- [`PATCH /v1/groups/:id/members/:userId`](/api-reference/groups) - the underlying HTTP route.

## `overridePermission(groupId, userId, permission, grant)`

Sets or updates a member-level permission override. Returns the `MemberPermissionOverride` row.

```ts
// Allow Alice to kick others, regardless of her roles' permissions.
await junjo.members.overridePermission(
  "grp_xyz" as GroupId,
  "user_alice" as UserId,
  "guild.kick" as PermissionKey,
  true,
);

// Block Bob from inviting members, even if his role allows it.
await junjo.members.overridePermission(
  "grp_xyz" as GroupId,
  "user_bob" as UserId,
  "guild.invite_member" as PermissionKey,
  false,
);
```

Overrides are the first resolution layer, so an override wins over any role-derived grant or deny (see [How a check is resolved](/sdk/permissions#how-a-check-is-resolved)). In `"nodes"` mode an override key may be a wildcard such as `shop.*`, and the most specific matching override decides. Idempotent: setting the same `grant` value twice returns the existing override unchanged.

The permission key is auto-registered into the per-game catalog on first sight (the same `PermissionDef` table populated by `roles.grantPermission`). Permission keys are 1-128 characters.

A fifth argument takes `ifMatch` and `idempotencyKey`. The returned override carries no member version; read [`getAccess`](#getaccessgroupid-userid) for the version after the write.

### Errors

| Code | Status | When |
|------|--------|------|
| `bad_request` | 400 | `grant` missing or non-boolean, or `permission` is empty / over 128 characters. |
| `not_found` | 404 | Group missing / soft-deleted / cross-game, or no `ExternalIdentity` for the user, or no `GroupMember` row in this group. |
| `precondition_failed` | 412 | `opts.ifMatch` does not match the member's version. Nothing was written. |
| `invalid_api_key` | 401 | API key missing, malformed, or revoked. |

### See also

- [`POST /v1/groups/:id/members/:userId/permissions/:permission`](/api-reference/groups) - the underlying HTTP route.

## `clearPermissionOverride(groupId, userId, permission)`

Clears a member-level permission override. Returns `void`. Idempotent: clearing a permission the member has no override for is a no-op.

```ts
await junjo.members.clearPermissionOverride(
  "grp_xyz" as GroupId,
  "user_alice" as UserId,
  "guild.kick" as PermissionKey,
);
```

After clearing, the member's effective permission for this key falls back to whatever their roles dictate.

A fourth argument takes `ifMatch` and `idempotencyKey`. The call returns nothing, so read [`getAccess`](#getaccessgroupid-userid) for the version after the write. The precondition is checked even when there is nothing to clear, so a stale queued clear is reported instead of silently succeeding.

### Errors

| Code | Status | When |
|------|--------|------|
| `not_found` | 404 | Group missing / soft-deleted / cross-game, or no `ExternalIdentity` for the user, or no `GroupMember` row in this group. The override's existence is *not* validated; an unknown permission key collapses to a no-op. |
| `precondition_failed` | 412 | `opts.ifMatch` does not match the member's version. Nothing was written. |
| `invalid_api_key` | 401 | API key missing, malformed, or revoked. |

### See also

- [`DELETE /v1/groups/:id/members/:userId/permissions/:permission`](/api-reference/groups) - the underlying HTTP route.

const overrides = await junjo.members.listPermissionOverrides(

## `getAccess(groupId, userId)`

Reads one member's direct role ids and permission overrides in a group, in one call. Returns `MemberAccess | null`: the SDK turns the server's `404 not_found` into `null`, like [`get`](#getgroupid-userid).

```ts
const access = await junjo.members.getAccess("grp_xyz" as GroupId, "user_alice" as UserId);
if (!access) return; // not a member

access.status;    // "active", "banned", ...
access.roleIds;   // roles held directly, not inherited ones
access.overrides; // MemberPermissionOverride[], sorted by permission
```

Together with [`roles.getGraph`](/sdk/roles#getgraphgroupid) this is everything a local resolver needs for one member: the graph supplies every role's entries and parents, and `getAccess` supplies where the member starts in it. It replaces a `get` plus a `listPermissionOverrides` with a single request.

### Returns

`MemberAccess`: `{ groupId, userId, status, roleIds, overrides, version, displayName }`. `displayName` is the person's display name or `null`. `version` is the member's version, usable as `ifMatch` for the member-scoped writes. `roleIds` lists only directly held roles; follow each role's `parents` in the graph for inherited ones. Each override has the same shape as the entries returned by [`listPermissionOverrides`](#listpermissionoverridesgroupid-userid).

### Errors

| Code | Status | When |
|------|--------|------|
| `invalid_api_key` | 401 | API key missing, malformed, or revoked. Thrown. |

`404 not_found` (group missing / soft-deleted / cross-game, no `ExternalIdentity` for the user, or no `GroupMember` row in this group) is converted to `null`; it is not thrown.

### See also

- [`GET /v1/groups/:id/members/:userId/access`](/api-reference/roles#get-v1groupsidmembersuseridaccess) - the underlying HTTP route.

## `assignRole(groupId, userId, roleId, opts?)`

Assigns a role to a member. Returns the updated `Member`. Idempotent: assigning a role the member already has returns the unchanged member.

```ts
const updated = await junjo.members.assignRole(
  "grp_xyz" as GroupId,
  "user_alice" as UserId,
  "role_officer" as RoleId,
  { actorUserId: "user_mod_jane" as UserId },
);
updated.roles; // includes "role_officer"
```

The role must belong to the same group as the member. Passing a role id that exists in a different group throws `JunjoError` with code `role_group_mismatch` (status 400). Passing a role id that does not exist at all throws `not_found` (status 404).

A member in any status (`active`, `left`, `kicked`, `invited`, `banned`) can have roles assigned; the SDK does not gate on `status`. Whether to assign roles to non-active members is a product call left to the caller.

`opts.actorUserId` is an optional external user id for the moderator performing the assignment. When supplied, it populates the audit entry's `actorUserId` and the `role.changed` event payload's `actorUserId`. Omit for unattributed / server-side calls; both fields stay `null`.

`opts.ifMatch` makes the assignment conditional on the member's version, and `opts.idempotencyKey` makes a retry safe. The precondition is checked even when the member already holds the role, so a stale queued write is reported instead of silently succeeding.

### Errors

| Code | Status | When |
|------|--------|------|
| `role_group_mismatch` | 400 | The role exists but belongs to a different group than the member. |
| `not_found` | 404 | Group missing / soft-deleted / cross-game, or no `ExternalIdentity` for the user, or no `GroupMember` row in this group, or no `Role` row at all. |
| `precondition_failed` | 412 | `opts.ifMatch` does not match the member's version. Nothing was written. |
| `invalid_api_key` | 401 | API key missing, malformed, or revoked. |

### See also

- [`POST /v1/groups/:id/members/:userId/roles/:roleId`](/api-reference/groups) - the underlying HTTP route.

## `removeRole(groupId, userId, roleId, opts?)`

Removes a role from a member. Returns the updated `Member`. Idempotent: if the member does not have the role assigned (whether the role exists in another group, exists but is unassigned, or does not exist at all) returns the unchanged member.

```ts
const updated = await junjo.members.removeRole(
  "grp_xyz" as GroupId,
  "user_alice" as UserId,
  "role_officer" as RoleId,
  { actorUserId: "user_mod_jane" as UserId },
);
updated.roles; // does not include "role_officer"
```

Other role assignments on the same member are preserved.

`opts.actorUserId` mirrors [`assignRole`](#assignrolegroupid-userid-roleid-opts): populates the audit entry and the `role.changed` event when supplied. `opts.ifMatch` and `opts.idempotencyKey` work as on `assignRole`.

### Errors

| Code | Status | When |
|------|--------|------|
| `not_found` | 404 | Group missing / soft-deleted / cross-game, or no `ExternalIdentity` for the user, or no `GroupMember` row in this group. The role's existence is *not* validated; an unknown role id is a no-op. |
| `precondition_failed` | 412 | `opts.ifMatch` does not match the member's version. Nothing was written. |
| `invalid_api_key` | 401 | API key missing, malformed, or revoked. |

### See also

- [`DELETE /v1/groups/:id/members/:userId/roles/:roleId`](/api-reference/groups) - the underlying HTTP route.

## `setNotes(groupId, userId, input)`

Updates the officer notes attached to a member. Both fields are diffed per-field against the stored row: supplying the same value as stored is a no-op for that field (no DB write, no audit entry, member returned unchanged).

```ts
await junjo.members.setNotes("grp_xyz" as GroupId, "user_alice" as UserId, {
  notesPublic: "great healer",
  notesPrivate: "do not promote yet",
});
```

Notes are scoped per-member (not per-game). `notesPublic` is conventionally visible to other group members in the dev's UI; `notesPrivate` is officer-only ("don't promote, has been late on raids"). Junjo stores them verbatim and never branches on them.

Pass `null` to either field to clear it. Omitting a field leaves it untouched.

```ts
// clear public notes; leave private notes alone
await junjo.members.setNotes("grp_xyz" as GroupId, "user_alice" as UserId, {
  notesPublic: null,
});
```

### Input

| Field | Type | Notes |
|-------|------|-------|
| `notesPublic` | string \| null \| undefined | Up to 5000 chars. `null` clears. Omit to leave alone. |
| `notesPrivate` | string \| null \| undefined | Same rules as `notesPublic`. |

### Options

A fourth argument takes `ifMatch` (the member's version) and `idempotencyKey`, as on [`setMetadata`](#setmetadatagroupid-userid-metadata).

### Returns

`Member` (the post-update wire format), with its new `version`.

### Errors

| Code | Status | When |
|------|--------|------|
| `bad_request` | 400 | Input has neither `notesPublic` nor `notesPrivate`, or one of them is over 5000 characters. |
| `not_found` | 404 | Group missing / soft-deleted / cross-game, or no `ExternalIdentity` for the user, or no `GroupMember` row in this group. |
| `precondition_failed` | 412 | `opts.ifMatch` does not match the member's version. Nothing was written. |
| `invalid_api_key` | 401 | API key missing, malformed, or revoked. |

### See also

- [`PATCH /v1/groups/:id/members/:userId`](/api-reference/groups) - the underlying HTTP route.
