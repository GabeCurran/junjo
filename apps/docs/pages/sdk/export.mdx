# export

`junjo.export()` streams a whole game out of Junjo as parsed records:
every person, group, role, membership, invitation, ban, sanction,
friendship and audit entry. The [Export API reference](/api-reference/export)
covers the route and the file it produces.

```ts
import { createWriteStream } from "node:fs";
import { Junjo } from "@junjo.io/sdk";

const junjo = new Junjo({ apiKey: process.env.JUNJO_EXPORT_KEY! });
const out = createWriteStream("survival.partial.ndjson");

try {
  for await (const record of junjo.export()) {
    out.write(`${JSON.stringify(record)}\n`);
  }
} finally {
  out.end();
}
// Reaching here means the end record arrived and its counts matched:
// rename survival.partial.ndjson to survival.ndjson.
```

## The key needs `canExport`

The export contains member notes, ban reasons and the audit log, so only
API keys marked `canExport` may read it. Every key starts without it.
Set it when minting the key, later through the
[admin API](/api-reference/admin) (`{ "canExport": true }` on the key), or
with the "Can export" toggle on the key in the dashboard. Without it the
first `next()` rejects with `permission_denied` (403).

Keep the export key separate from your game server's everyday key.

## `junjo.export(opts?)`

```ts
export(opts?: ExportOptions): AsyncGenerator<ExportRecord>;

interface ExportOptions {
  signal?: AbortSignal;
  records?: readonly Exclude<ExportRecordKind, "game">[];
  groupKinds?: readonly string[];
}
```

Opens `GET /v1/export` with the client's base URL, key and `fetch`, and
yields one parsed record per line as it arrives. The body is read as a
stream: at most one line is held in memory, so exporting a large game
does not grow your process. Breaking out of the loop closes the
connection.

The client timeout does not apply, since a large game streams for as
long as it takes. Pass `signal` to bound or cancel it; an abort rejects
with `cancelled`.

### Filters

`records` and `groupKinds` are sent as the route's [query parameters](/api-reference/export#get-v1export):

- `records`: the record kinds to export, any kind except `game`. Omitted: every kind. The header, `game` and end records always arrive.
- `groupKinds`: keeps the group-scoped records (groups, roles, members, invitations, relationships by their A side, and the group rows of ban history and audit) of groups of these kinds only. Game-scoped records are not affected; leave them out with `records`.

```ts
for await (const record of junjo.export({
  records: ["group", "role", "member"],
  groupKinds: ["guild"],
})) {
  // only guilds, their roles and their members
}
```

An empty list, an unknown kind, more than 32 group kinds or a group kind over 64 characters rejects with `bad_request` on the first `next()`.

### Records

Each record is a JSON object discriminated on `kind`. They arrive in this
order:

1. `header` (first): `{ kind, format: "junjo-export", version: 1, gameId, exportedAt, position, records, groupKinds }`. `position` is the game's [stream position](/sdk/events#positions), read before any record. `records` lists the kinds the export carries (without `game`) and `groupKinds` the group kinds it was limited to, or `null`.
2. Records grouped by kind: `game`, `person`, `group`, `role`, `member`, `invitation`, `relationship`, `ban`, `banHistory`, `sanction`, `sanctionHistory`, `friendship`, `friendRequest`, `block`, `friendTag`, `audit`. A kind with no rows has no records.
3. `end` (last): `{ kind: "end", counts }`, the number of records per kind; a kind left out by `records` counts `0`.

```ts
for await (const record of junjo.export()) {
  switch (record.kind) {
    case "header":
      saveResumePosition(record.position);
      break;
    case "person":
      for (const id of record.identities) indexName(id.userId, id.displayName);
      break;
    case "group":
      // record.version: the group's version for the exported state
      break;
    case "member":
      // record.personId, record.groupId, record.roles, record.version, ...
      break;
    case "unknown":
      // A kind newer than this SDK: record.rawKind, record.record.
      break;
  }
}
```

Records are passed through as the server wrote them: timestamps stay ISO
strings and ids stay plain strings, so a file can be written back out
unchanged. They refer to each other by internal ids (`id`, `personId` and
fields ending in `PersonId`); `userId`, `actorUserId` and `targetUserId`
hold external ids. A group's kind is `groupKind` and a history row's kind
is `historyKind`, because `kind` names the record. The field list for
every kind is in the [Export API reference](/api-reference/export#record-kinds),
and each has a type exported from `@junjo.io/sdk`
(`ExportPersonRecord`, `ExportMemberRecord`, and so on).

A line whose `kind` this SDK version does not know arrives as
`{ kind: "unknown", rawKind, record }`, so a newer server does not break
an older reader.

### Truncation and errors

A file without its end record was cut short. `junjo.export()` checks this for
you: when the stream ends without the end record, or the end record's
counts disagree with the records that arrived, it rejects with
`invalid_wire_data`. That rejection comes after every record that did
arrive has been yielded, so write to a temporary file and keep it only
once the loop finishes without throwing.

| Code | When |
|------|------|
| `bad_request` | `records` or `groupKinds` is empty or names something invalid. |
| `permission_denied` | The key does not have `canExport`. |
| `invalid_wire_data` | The stream ended without the end record, the counts disagree, the first line is not the header, data follows the end record, or a line is not a JSON object with a string `kind`. |
| `network_error` | The connection failed mid-stream. Export again; the export does not resume. |
| `cancelled` | `opts.signal` aborted. |
| `stream_overflow` | A single line passed `EXPORT_MAX_LINE_CHARS` (about 16 MiB of text) without a newline. |

## Staying exact

The export is not one database snapshot: a write made while it runs may
or may not be in it. To stay exact, restore the file and then replay the
[game stream](/sdk/events) from the header's `position`; every change made
during the export is in that range.

```ts
let position: string | undefined;
for await (const record of junjo.export()) {
  if (record.kind === "header") position = record.position;
  await restore(record);
}
const sub = await junjo.events.subscribe(applyChange, { from: position });
```

## Never exported

API keys, group passcode hashes (only `hasPasscode`), webhook endpoints
and deliveries, link codes, idempotency records and the event log.
